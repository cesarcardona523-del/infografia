ETL, ELT, ETLT y Reverse ETL: Cuándo Transformar el Dato

Los cuatro patrones se diferencian por cuándo ocurre la transformación — antes de cargar, después, en ambos momentos, o en sentido inverso hacia el negocio.

ETL
Extract → Transform → Load
Extract
Datos crudos de la fuente
Transform
Limpieza y reglas de negocio
Load
Se carga ya transformado
Resultado
Datos listos, pipeline rígido
Mejor para BI tradicional y reportes con esquema estable y gobernanza estricta desde el origen.
Transforma antes de cargar — clásico en data warehouses tradicionales.
ELT
Extract → Load → Transform
Extract
Datos crudos de la fuente
Load
Se carga sin transformar
Transform
Se transforma dentro del warehouse
Resultado
Flexible y reprocesable
Mejor para Volúmenes grandes en cloud warehouses modernos (Snowflake, BigQuery, Databricks).
Aprovecha el cómputo del warehouse (dbt, SQL) — el crudo queda disponible.
ETLT
Extract → Transform → Load → Transform
Extract
Datos crudos de la fuente
Transform
Limpieza básica / PII
Load
Se carga al warehouse
Transform
Modelado analítico completo
Resultado
Gobierno + flexibilidad
Mejor para Arquitecturas medallón que necesitan enmascarar datos sensibles antes de aterrizarlos.
Híbrido: transformación ligera antes, pesada después — común en medallón.
REVERSE ETL
Extract (warehouse) → Transform → Load (herramientas)
Extract
Datos ya modelados del warehouse
Transform
Se adaptan al esquema destino
Load
Se cargan en CRM / Ads / Soporte
Resultado
Datos operacionalizados
Mejor para Activar métricas del warehouse directamente en CRM, ads o herramientas de soporte.
El flujo inverso: lleva el dato YA analizado hacia donde trabaja el negocio.
La diferencia real no es solo el orden de las siglas: ETL/ELT/ETLT mueven datos crudos hacia el warehouse; Reverse ETL mueve datos ya modelados desde el warehouse hacia las herramientas donde opera el negocio (CRM, ads, soporte) — sin ese último paso, el análisis se queda en el dashboard.
