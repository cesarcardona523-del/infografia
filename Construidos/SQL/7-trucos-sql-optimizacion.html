Database Architecture & Tuning

7 Trucos SQL para Código Óptimo

Pequeños cambios arquitectónicos que marcan una gran diferencia en rendimiento y mantenibilidad.

1. Proyección Específica
Evita SELECT *. Consultar solo las columnas requeridas reduce la carga en memoria y el I/O del disco.
-- Práctica optimizada
SELECT id, nombre, email
FROM clientes
WHERE estado = 'activo';
2. Índices Estratégicos
Índices B-Tree en columnas frecuentes convierten escaneos secuenciales en búsquedas logarítmicas.
-- Creación de índice
CREATE INDEX idx_users_email
ON usuarios(email);
3. JOINs Explícitos
Un JOIN implícito (con comas) puede ser ambiguo. Usa sintaxis ANSI explícita para evitar productos cartesianos.
SELECT u.nombre, p.titulo
FROM usuarios u
INNER JOIN posts p
  ON u.id = p.user_id;
4. Refactorización (CTE)
Sustituye subconsultas anidadas complejas por expresiones WITH (CTEs) para modularizar la lógica.
WITH Ventas_CTE AS (
  SELECT * FROM ventas
)
SELECT * FROM Ventas_CTE v;
5. Semántica con Alias
Asignar AS a tablas y columnas calculadas auto-documenta la salida de datos.
SELECT
  u.id AS user_id,
  COUNT(p.id) AS total_posts
FROM usuarios u;
6. Tolerancia a Fallos
Prevé valores NULL inesperados usando COALESCE() para fallbacks seguros.
-- Fallback si es NULL
SELECT
  COALESCE(telefono, 'N/A')
FROM clientes;
7. Paginación y Límites
Protege el servidor de colapsos por falta de memoria aplicando límites estrictos a consultas abiertas.
SELECT id, status
FROM logs_sistema
ORDER BY fecha DESC
LIMIT 100;
